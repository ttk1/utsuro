# ゲーム仕様（game/index.html）

今の仕様だけを書く。変えた経緯と理由は `docs/経緯と決定事項.md` にある。

## 概要

- 単一 HTML・外部ライブラリなし。ブラウザで直接開けば動く。ローカルでは `docker compose up` で http://localhost:8080/ に配信できる（nginx、`tools/nginx.conf`）。公開は GitHub Pages（`.github/workflows/deploy.yml`）
- CSP は `index.html` 冒頭の meta で指定している。外から読むのは Google Fonts だけで、それ以外の外部通信・外部スクリプト・音声ファイルは使えない。新しく外部のものを読むときは CSP も直す
- 第一話「無人放送」（序章＋全5章）と第二話「不在証明」（全7章）を収め、タイトル画面で選ぶ。第一話の終わりから第二話へ進める
- 進行状況は話ごとに localStorage に保存する（第一話 `utsuro-save-v5`、第二話 `utsuro2-save-v3`。古いキーのデータは読まない）。話をまたぐ設定（対決の時間制限 `timer`、効果音 `sound`、つかみを見たか `cold`）は `utsuro-pref-v1` に持つ。データ構造を変えたら、その話のキーを上げる
- 「事件ファイル」メニューの「最初からやり直す」は、今遊んでいる話の進行状況だけを消す

## 遊びの流れ

章ごとに「その時代の端末」のデスクトップが開き、アプリをウィンドウで開いて調べ、「捜査ノート」アプリ（`data-win="note"`）に出る問題に答える。答えるたびに次の問題までスクロールし、正解した問題は一瞬光る。

### 問題の種類（`steps`）

- `text`：自由入力。`check(v)` で判定する（入力は NFKC 正規化・空白除去・小文字化済み）。`traps` は [正規表現, 誤答時の返事]。架空の固有名は読みでも正解にする（とうわん、つきみだい、たかぎ、ぽけっと、ひいらぎ など。スマホでは変換しにくいため）。看板・建物名は中黒やひらがな・カタカナの混在を受け付ける
- `pick`：証拠をつかんで結びつける（下の節）
- `present`：集めた証拠から一つ選んで突きつける（対決と、第二話 第六章）
- `op`：アプリの中の操作で解く。`op` に操作の名前（`breach`）を書き、アプリの側が `solve(c, i, 表示する答え)` を呼ぶ。答えの欄はない（第二話 第四章の侵入の場面だけ）
- `choice`（単一選択、`answer` はインデックス、`why(i)` が誤答の返事）・`multi`（複数選択、`answer` はインデックスの配列、`why(sel)`）：一覧から選ぶ問題は総当たりで解けて問題集に見えるので、第二話の 3 問（「。」の理由、柊が映像を出せない理由、持ち主を来させる方法）だけに残している。増やさない
- 問題文には結論を書かない。主人公の引っかかりと「何を見比べるか」を書き、結論は解いたあとの答え（`shown`）・メモ（`memo`）・解明（`solved`）に出す

### 証拠をつかむ（`pick`）

- 問題が `pick` のあいだ、開いているウィンドウの中の「つかめる要素」（`data-ev` の付いた記事・表の行・メッセージ・カード・見取り図の印）が点線で囲まれ（`#wins.picking`）、押すとノートの枠（`.slots`）に入る。もう一度押すか、枠の×で外れる。枠がいっぱいのときは、いちばん古いものと入れ替わる。キーボードでは Tab で要素に移り Enter でつかむ
- 枠がそろったら「結びつける」（枠が一つなら「ここに決める」）で判定する。`check(sel)` は、正解なら `true`、誤答なら返事の文字列、方向は合っているが足りない組み合わせなら `{hold:文字列}`（誤答に数えない）を返す
- 正解だけでなく、同じ種類の要素はすべてつかめる（表なら全行。正解だけ光ると総当たりになるため）
- ハッシュ値の行は、つかんだ 2 行がそのまま比較の欄（`#hcmp`）にも出る
- 明るい紙のカード（`.doc`・`.news`）は、つかめる・つかんだ状態の強調でも明るい色のままにする（透ける色を重ねると下の暗いウィンドウが透けて、黒い文字が読めなくなる）
- 幅 760px 以下ではノートが別のウィンドウの裏に回るので、つかんだものを下の帯（`#pickbar`）に出す。帯のボタンは、枠がそろうまで「ノートへ」、そろうと「結びつける」／「ここに決める」（`data-go`。押すとノートを開いてそのまま判定する）

### 証拠

- 問題を解くと、その問題の `ev` の証拠が手に入る（解いた問題の下に「手に入れた証拠」と出る）。章に入った時点で手に入るものは章の `ev` に書く。中身は話ごとの一覧（`EV1`・`EV2`、id → [題, 中身]。中身は関数でもよい）
- 一覧（`evHave`）は新しく手に入れた順に並ぶ。対決・第二話 第六章の一覧では、その章で手に入れたもの（章の `ev` と、その章で解いた問題の `ev`）に「新」と付く。題だけを並べ、選んだものの中身を開く
- 第二話 第六章・第七章には、手に入れた証拠をカードで見る「手元の証拠」アプリがある（`evCards`）

### 対決

- `tag` が「対決」「最後」で始まる問題が対決（`isDuel`）。第一話 第五章（久我）と第二話 第七章（榊原）の後半。「対決 n」は `present`、「最後」は `text`（開けさせる場所・出させるもの）
- 相手の言い分とゲージは、ノートの上に貼りつく欄（`.duelhead`）に置き、その下の一覧から証拠を選んで「突きつける」。ボタンは `.evgo` に入っていて、幅 760px 以下ではノートの下端に貼りつく（見出しとボタンのあいだで一覧だけがスクロールする）
- 誤答のときは、相手の言い返しのせりふを語りに出し、ノートには「次に見るところ」と、あと何回で相手が立て直すかだけを出す。言い返しは、証拠ごとの `why`、章を通して出せない証拠の `taboo`、どちらもなければ章の `rebut`（相手の口調の決まった言い返し 3 種）を順に使い、`nudge`（次に見るところ）を添える。`hold` に書いた証拠は「まだ出さない」と返し、誤答に数えない
- 3 回まちがえると相手が立て直し（章の `foe`・`retreat` のせりふ）、一つ前の言い分に押し返される（その言い分をもう一度崩す。最初の言い分でまちがえたときは、そのまま）。最初までは戻さない（解いた言い分を全部選び直すのは作業になるため）。まちがえた数は `S.duel[章id]` に持ち、押し返されると 0 に戻る
- 言い分を崩すと、ノートに残る相手のせりふ（`.brkq`。「どの証拠を突きつける？」は落とす）に取り消し線が左から走り、「✓ 崩した ― 証拠の題」が一拍遅れて押され、問題が光って小さく揺れ、画面の上端のゲージも一瞬光る。効果音は `brk`。次のせりふ（次の問題の `lead`。崩した直後の主人公の一言と相手の反応、小説の第五章・第七章に合わせてある）は 0.7 秒おいてから出はじめる（`narrate` の `beat`。待っているあいだに押せばすぐ出る）。`prefers-reduced-motion` では線と文字を動かさず、初めから引いた形で出す
- 対決の `why` は、相手の言い返しの形で書く（`久我「…」 ― 次に見るところ`）。`「…」` の部分が語りに、` ― ` のあとがノートに出る
- 第一話の対決 1 は、貨物の音のほかにハッシュ値の一致・ループの素材でも崩せる（どれも「配信はライブではない」を示すため）。第二話では、警備会社のサーバーで見た元の映像（`raw`）は線を越えて見たもので、第七章のどの言い分に出しても誤答になる（`taboo`）

### 対決の時間制（ゲージ）

- 対決のあいだは、相手がしびれを切らすまでの残り時間をゲージで出す（ノートの問題の中の `.fusebox` と、画面の上端の細い線 `#fuse`。見出しは章の `fuse`）。一つの言い分につき 90 秒（`FUSE_MAX`）
- 切れたら 1 回まちがえたのと同じ扱いにして、相手の一言（章の `timeout`）を語りに出し、ゲージを戻す。正解でも誤答でもゲージは満タンに戻る（残りわずかで誤答 → すぐ時間切れ、の二重の罰を避けるため）
- 止まるとき：タブが隠れている、メニュー・タイトル・章扉・エンディングが出ている、言い分がまだ出ていない（`NR.hold`。このあいだゲージは隠す）。語りに読んでいない続きがあるあいだも止まるが、一つの言い分につき合計 20 秒まで（`NARR_GRACE`。上限がないと、語りをわざと読み終えずにおけば時間を使わずに考えられてしまう）。猶予はゲージが満タンに戻るたびに戻る
- 「事件ファイル」メニューの「対決の時間制限：あり／なし」で切り替えられる（`PREF.timer`）。`prefers-reduced-motion` のときは初めから「なし」

### 第二話 第六章「見逃す」（架純の疑問）

- 対決の裏返し。架純は敵ではなく、警察官として疑問を一つずつ口にし、ミオは誰でも確かめられるもの・持ち主が差し出せるものだけで答える。仕組みは `present` だが `tag` を付けないので対決の扱いにならない（ゲージも、3 回での押し返しもない）。章の `foe`（架純）と `rebut` は、まちがえたときの架純の返事を語りに出すために使う。ボタンの文字は章の `btn`（「これで応える」）
- 章の `pass`（`[題, 中身, 出すものがある問いで選んだときの相手のせりふ, 解いたあとに表示する答え]`）があると、証拠の一覧の最後に「何も出さない」（値 `pass`）が出る。`answer` に `pass` のない問いで選ぶと、相手のせりふを語りに出し、誤答に数えない。最後の問い（「どうして、その時刻を知ってるの」）だけは `answer:['pass']` で、黙ることが正解になる（章の主題「見逃す」）。問題ごとの `rebut` で、決まった言い返しをその問いだけ差し替えられる
- 柊が名乗るのは、定点カメラを見せた直後（3 問目の `lead`）。小説では「聞かないでおく」のあとで、順が違う（ユーザーの判断でこのまま）

### 第二話 第四章の侵入の場面（`breach`）

- 4 問目を解くと、ミオの古いノートPCの「端末」アイコンが現れる（`after:4`）。5 問目は `op:'breach'`
- `connect tohto-sec` → `ls`（日付の一覧）→ `ls 0928`（その日に動きを検知した時刻）→ `play 0928 0037` と `play 1011 0421`（映像が端末の中に出る。`9/28 0:37` のような書き方も受ける）→ `copy` するかしないかを選ぶ → `wipe`（入った跡を消す）→ `exit`。写しを持ったままでは切れず、`delete` で自分で消すことになる。`connect` の返事は一行ずつ間をおいて出る（`.stg`。打った直後だけ動かし、ログには動きのない形で残す）。つないでいるあいだはプロンプトが `tohto-sec >` になり（`term.prompt`）、端末の上の縁の色が変わる
- 一度でも写したかは `S.copied` に残り、第四章の解明、`raw` の中身、第六章・第七章の返事、エンディングの透との会話、「この話の記録」が変わる。小説ではミオは何もコピーしない
- コマンドはすべて架空のもので、実在の攻撃手法・脆弱性・ツール名・手順は書かない。状態は `BR`（`freshBR`）、映像は `BRCLIP`、日付と検知の一覧は `BRDAYS`・`BRLS`

### 第二話 第七章の準備と時計

対決の前に「準備」の問題（`pick`、枠一つ）がある。見取り図の 1〜5 から待つ場所を選ぶ（正解はカメラの真下の 5）。決めると画面の時計が 00:10 から 03:41 まで早回しで進み（章の `clock2`、`runClock`）、榊原が来る。

### 語りとノートの出し方

- 語り（`#narr`）はクリックで一行ずつ進み、一文字ずつ出る。章の語り `narr` を読んだ位置は `S.nr` に持つ（いちばん先まで読んだ行。戻って読み返しても減らさない）
- 章の最初の問題と `lead` のある問題は、種類にかかわらず、その語りを読み終えるか語りをしまうまでノートに出さない（`NR.hold`。そのあいだノートには「……」と「下の語りを読み進めよう」だけを出し、証拠をつかむこともできない）。物語が一行も進まないうちに入力欄が見えると問題集に見えるため。相手の言い分から始まる章では、語りより前に相手の言葉が見えないようにするためでもある。読み終えた章に入り直したときは待たせない
- 語りの行には、その行が出たときに動かす仕掛けを付けられる（行の 4 番目の要素の関数）。第一話 第二章では「黒い画面が、ふっと明るくなった」の行（`LIVE_AT`）で配信のウィンドウに部屋が映る。語りをしまったときは、残りの行の仕掛けをまとめて動かす
- 語りは解く前に方法を説明しない。第一話 第一章では、書き方の違いをつかんだあとの `lead` で、透がログに目を向ける（「文体だけなら、本人がわざと変えたのかもしれない。だから、ログが要る」）
- 解明の文章（`solved`）は語りにも流れ、語りで読み終えた段落までをノートに出す（`NR.sol`、`solvedHTML`、`drawSolved`）。最後の行を出しきるか語りをしまうと、全部と「次の章へ」のボタン（文字は章の `next`、既定は「次の章へ」）が出る。解いた章を読み返すときは初めから全部出す
- 語りの最後の行には、章を解き終えていれば次へ進むボタン（`data-nn`。文字と動きはノートと同じ `nextLabel`・`goNext`）が出る。それ以外の最後の行には「捜査ノートとアプリで調べよう」と添える
- 問題を解いたとき・対決で押し返されたときに語りが開くのは、場面の切り替わりなのでそのまま（ノートの中身も入れ替わる）
- 気づき：アプリの中で何かに気づく操作をすると、語りに一言だけ差しこむ（`react(key, 行)`。話ごとに一度きりで `S.seen['r-…']` に持つ。読みかけの語りの続きはそのあとに残る）。第一話は、左右反転（`flip`）、録画を最後まで再生（`live`）、最古の保存版（`ipcam`）、解析IDの逆引き（`ua`）、ハッシュ値の一致（`hash`）、明るさ補正 ×5 以上（`fig`）、差分表示（`seam`）。第二話は、`trace`（「木の名前が並んでいる。最後の一つだけが、日本語ではない」）、回線の記録の 10/11（`net`）、侵入の場面で映像を見たとき（`br0928`・`br1011`・`brboth`）
- 語りに差しこむ一言は `say` を通す。幅 760px 以下では語りを開かず書き換えず、ウィンドウの上に重ねて 9 秒出し（`whisper`、`.whisper`。続けて届けば同じ枠に足す。押すと語りが開く）、語りには「次の行」として残す。語りをたたんでいるときは、タスクバーの「語りを表示」に赤い印（`#narrBtn.new`）を付け、開くとその行から読める（`NR.pend`、`openNarr`）。語りが開くとウィンドウが下から縮み、押していた入力欄やボタンが上にずれるため。誤答のときの相手の言い返し、「何も出さない」への返事、侵入の場面で写しを消したときの一言も同じ
- チャットは自動では開かない。通知（`.toast`）とアイコンの未読の印で知らせ、初めて開いたときだけ入力中の表示をはさんで一通ずつ届く（`S.seen`）。通知と印は、章の語りが `chat.at` の行に届いてから出す（`chatDue`・`chatNotify`。第一話 第一章は「スマホが震えた」の行。`at` がなければ章の頭）。前に届いたメッセージを読み返すだけのチャット（`quiet:true`。序章と第二話）は、通知・未読の印・入力中の表示を出さない

### ヒントと記録

- `hints` は問題ごとの配列（`hints[i]` が `steps[i]` のヒント。1〜2 個を順に開く）。いま解いている問題の中に「ヒントを見る」が出る。開いた数は `S.hints['章-問']` に持つ。開くときはヒントの欄だけを書き換える（ノート全体を作り直すと、入力途中の答えやつかんだ証拠が消えるため）
- 誤答の数（`S.miss`。時間切れを含む）と開いたヒントの数は、エンディングの最後に「この話の記録」として出す（`recordHTML`）。第二話は、警備会社の映像を写したかどうかも出す。タイトル画面のボタンは、全問を解いた話に「解決済み ・ 読み返す」、途中なら「つづきから」と出す

### 効果音と配信の音

- 効果音（`SFX`・`sfx(名前)`・`audio()`）は Web Audio で合成する（`AudioContext` は配信の音 `liveSound` と共有）。初めは OFF で、タイトル画面の `#tsound` か「事件ファイル」メニューの `#msound`（「効果音：あり／なし」）で切り替える（`PREF.sound`、`toggleSound`）。「あり」にしたときは確かめられるように一つ鳴らす。`prefers-reduced-motion` とは独立。`AudioContext` のない環境（jsdom）では何もしない
- 鳴らす場面は 8 種類だけ：`grab`（証拠をつかむ）・`drop`（外す）・`find`（気づきの一言 `react`）・`ok`（正解）・`bad`（誤答・時間切れ）・`brk`（対決で言い分を崩す。低い音に短いノイズを重ねる）・`chapter`（話を始める、次の章へ、エンディングへ）・`toast`（通知）。各音は `[周波数, 長さ, 音量, 波形, 始まるまでの秒, 終わりの周波数]` の並びで、長さは 0.06〜1.5 秒、音量は 0.03〜0.11。語りを進める、ウィンドウを開くといった頻繁な操作には付けない
- 第一話 第二章の配信の音（50Hz のハム音と低いノイズ、通過音）は、録画のプレーヤーのボタン（`#lvsnd`「音 ON／OFF」）で切り替える別の設定。効果音が「あり」のときは初めから ON で開く。つかみでも、効果音が「あり」なら部屋が映っているあいだだけ同じ音を鳴らし、黒に戻ると同時に切る（始まりの `chapter` は、つかみのあと序章に入るときに鳴らす）

## 画面

### 画面の流れ

- タイトル画面（`#title`、話を選ぶボタン `#start`・`#start2`、効果音 `#tsound`）→ つかみ（`#cold`。第一話を初めて始めるときだけ）→ 章扉（`#card`）→ デスクトップ（`#screen`）→ エンディング（全面表示 `#endov`）
- タイトルの背景は配信の部屋（`roomSVG`）。ゆっくり明るさが変わり、縦長の画面では高さに合わせて広げて時計と窓のあたりを見せる。惹句の下に「次の配信まで」を出す（`drawCast`、`#cast`。遊んでいる人の時計で、次の午前 3 時 33 分までを 1 秒ごとに数える。03:33 からの 11 分間は「配信中」になり、部屋がはっきり映る）
- つかみ（`coldOpen`）：題材の絵を説明より先に見せる、14 秒ほどの場面。黒い画面に utsuro.tv のトップページの文句（`SITE_TOP`）と時計 3:32 → 3:33 に変わる → 部屋が映る（LIVE、視聴 11 → 12）→ 6 秒は何も起きない → 残りの十一分を 3 秒で早回し（貨物の通る二度だけ画面が揺れる）→ 03:44 に何も出さずに黒 → 序章の章扉。押すか Enter・Esc で飛ばせる。見たら（飛ばしても）`PREF.cold` に残し、二度目からは出さない。進行状況のある第一話を「つづきから」で開くときも出さない。`prefers-reduced-motion` では、にじませず早回しもせず、部屋を 3.5 秒だけ見せる
- 章扉は、前の章から続けて開いたときだけ起動の表示（章の `boot`）を出す。出るときは一瞬で覆い（にじませると、覆いきる前に次のデスクトップが透ける）、消えるときだけ 0.6 秒かける。消えていくあいだもタップを受け止める（`visibility` を遅らせて消す。`pointer-events:none` にすると、飛ばそうと押した指が下のノートのボタンに当たる）
- タイトルの惹句と注意書きは、句の切れ目（`.nb`）でだけ折り返す
- エンディングは話ごとの関数（`ending1`・`ending2`）が返す。第一話の終わりには第二話へ進むボタン（`#toEp2`）、第二話の終わりにはタイトルに戻るボタン（`#endTitle`）がある

### デスクトップとウィンドウ

- 左にアイコン（`#icons`）、ウィンドウ（`#wins`）、下に語り（`#narr`）、タスクバー（`#bar`。「事件ファイル」メニュー・開いているウィンドウ・「語りを表示」・時計）
- 壁紙（`WALL`）はテーマごと。右下に透かし文字（章の `mark`。2026 年の章は透のハンドル名 ghostwire、2036 年の事務所は SHINOMIYA RESEARCH、ミオの古いノートPCは空）
- ウィンドウはドラッグ・最小化・閉じるができ、大きさは右下のつまみ（`.rz`）で変える。CSS の `resize` は、大きい画面で `zoom` をかけるとポインタより大きく動くので使わず、移動と同じくマウスの移動量を拡大率で割っている
- 置き場所は `placeWin` が決める。開いているウィンドウと語りになるべく重ならない場所を粗い格子で探し、広い画面では並べ、空きがなければ重なりのいちばん少ない所に置く（別のウィンドウとタイトルバーが重なる位置は避ける）。章に入るときは、語りを出してからウィンドウを開く（語りの位置を避けるため）
- 捜査ノート（`NOTE`）は右上に開く。語りの右に収まるなら縦いっぱいに開き、対決・`present` のある章では広い幅で開く（`openApp` の `wide`。証拠の一覧 `.win.wide .evlist` は二列になる）。ノートが右下まで開いているときは、通知を左下に出す
- 章を切り替えたら、前の章のウィンドウと通知は消す
- 時計は章の `clock`（作中の日時）を出す

### アプリの仕掛け

- 地図（`#mapapp`、`PLACES`・`mapSVG`・`placeCard`）：検索とピン。場所の詳細（`#pcard`）はウィンドウの下端に貼りつけて出し（`position:sticky`）、ピンを押しても地図は動かない。狭い画面では欄を低くし、続きは欄の中をスクロールする
- 端末（`#tout`、コマンド → 出力は話ごとの `TERM1`・`TERM2`、知らないコマンドは `term1Fallback`・`term2Fallback`）：↑↓ でコマンド履歴、実行ボタン（⏎）。出力の折り返しは `overflow-wrap:anywhere`（時刻やコマンドの途中で切らない。長い URL やハッシュ値だけ途中で折れる）。候補（`#tchips`）は二段で、上はコマンド（話ごとの `term.chips`。場面によって変わる）。引数の要らないもの（末尾に空白のない `help`・`history`・`wipe`・`exit`・`connect tohto-sec` など）は押すとそのまま実行する。下は引数の候補（`term.args`）で、横にスクロールする一列。押すと入力欄の続きに足す（`/` で始まるパスは直前のドメインにつなげる）。第一話は `term1Args` が、これまで端末に出たドメイン・パス・解析 ID・8 桁の日付を、新しいコマンドの出力から順に 9 個まで拾う（画面に出ていないものは候補にしない）。第二話は `utsuro.tv` だけで、侵入の場面では出さない
- 第二話の端末（ミオの古いノートPC）は `whois`・`curl`・`trace`。`trace` の出力の注記に「並べた名前の中に、自分の名前を一つだけ混ぜる人がいる」とある。中継のホストを調べたときの返事は「手がかりは、名前の付け方だけだ」
- ハッシュ比較（`#htab`、`HASH`）、差分表示（`#dbox`、`mix-blend-mode: difference`）、明るさ補正スライダー（`#br`、×1〜×8）
- 映像の拡大（`initZoom`）：`.zoomable` の中の映像（`.stream`）は、押した場所を拡大できる（第一話の 10/11 の録画、第二話の事務所の録画・定点カメラ・週刊誌の写真）
- 配信の録画（`initLive`、第一話 第二章）：章に入ったときは配信前の黒い画面（`#live.pre`。トップページの文句だけが出て、操作のボタンは隠す）で、語りが「黒い画面が、ふっと明るくなった」に届くと部屋が映る。再生は 11 分を 20 倍速で流し、始まりは黒から明るくなり、03:38 と 03:41 に通過音（画面が小さく揺れ、キャプションが出る）、03:44 に LIVE の表示も残さず黒くなる（`#live.ended`）。「左右反転」で映像を鏡に映した向きに直せる
- 配信を見ている画面（つかみと、この録画）には、薄い帯をゆっくり流す。明るさ補正・差分・拡大など手がかりを読む解析の画面には、動くものを足さない（手がかりと紛れるため）
- 回線の記録（`initNet`、第二話 第五章）：日付を切り替え、グラフを押すとその 1 分に白い線（`#netsel`）を引き、時刻と送信量を出す。「‹ 1分」「1分 ›」（`data-net`）で 1 分ずつ動かせる（スマホでは棒 1 本が 3px ほどで、指では狙えないため）
- Web 検索（`initSearch`、`SRCH`、第二話 第四章）：入力欄の例は答えにならないもの（「柚木台 マンション」）にしている
- アプリに `after:n` を付けると、その章の問題を n 個解いたあとにアイコンが現れる（第二話 第四章の端末、第五章の来訪メモ）
- 入力欄（解答・端末・地図・検索）は自動入力・自動修正を切っている。iPhone の Safari は `autocomplete="off"` を無視してパスワードなどを出すことがあるので、名前を `search-…` にしている（Safari は名前に search を含む欄に自動入力しない）

### スマホ（幅 760px 以下・タッチ操作）

- アイコン・ウィンドウ・語りを縦に並べ、ウィンドウは一枚ずつ残りの高さいっぱいに開く。アイコンは横一列（6 個まで収まる）、タスクバーのボタンはアイコンだけにする
- 通知は語りのすぐ上（語りをしまっていれば下の帯かタスクバーの上）に出し、ウィンドウを開いたら消す（`toastPos`。上に出すと、ウィンドウの×ボタンやノートの章題に重なる。語りの高さは行ごとに変わるので、語りを書き換えるたびに位置を合わせ直す）
- 表は折り返して幅に収め（右の列の手がかりに気づけるように）、地図は縮めず横スクロールにして中央から見せる
- 文字の入力中は語りをしまい、入力欄から離れて 0.5 秒後に戻す（先に戻すとタップ位置がずれるため。iPhone はタップ中に仕掛けた 0.4 秒以内のタイマーで要素が現れるとクリックを取り消すため、それより長くする）
- 語りを最後まで読み終えていれば、アイコンからアプリを開くときに語りをたたむ（章を解き終えたあとは、次へ進むボタンがあるのでたたまない）。対決・第六章では、証拠を選ぶと語りをたたむ（読み終えているときだけ）。気づきの一言は `whisper` で出す（「語りとノートの出し方」）
- 語りの下の行（行数と案内）は折り返さない（行数の表示が変わっても語りの高さを変えないため）
- 下の帯（`#pickbar`）には `position:relative; z-index:1` が要る（壁紙と透かし文字が上に重なるため）
- 貼りつく要素（`position:sticky`。対決の見出し `.duelhead`、「突きつける」の `.evgo`）は、スクロールする枠（`.bd`）の余白の内側が基準になるので、`top`・`bottom` を余白のぶん（`-16px`）ずらす（足りないと、すぐ隣の行に重なる）
- タッチ操作（`pointer:coarse`）では、ウィンドウのボタン・端末の候補・ヒントのボタン・スライダーを大きくし、入力欄の文字を 16px にする（iPhone が入力のたびに画面を拡大しないため）。語りを続けてタップしても拡大しないよう `touch-action:manipulation` にしている
- iPhone はキーボードを出すとページ全体をずらし、閉じても戻さないことがあるので、入力欄から離れたら `scrollTo(0,0)` で戻す

### 大きい画面

`#screen` と全面表示（`.over`）に `zoom` をかけて UI を段階的に拡大する（2400×1250 以上で 1.25 倍、2880×1500 で 1.5 倍、3360×1750 で 1.75 倍、3840×2000 以上で 2 倍）。基準はフル HD（ブラウザの枠を除いて約 1920×1000）。ウィンドウのドラッグとつまみは、マウスの移動量を拡大率で割って CSS の px に直している。

## データ構造

- `EPS`：話ごとの設定。`key`（保存キー）, `title`, `file`（事件ファイルのメニューの見出し）, `ch`（章データ `CH1` / `CH2`）, `ending`（終章の HTML を返す関数 `ending1` / `ending2`）, `evid`（証拠の一覧 `EV1` / `EV2`）, `term`（端末の `cmds`・`fallback`・`banner`・`chips`・`args`、第二話は `prompt`。`chips`・`args`・`prompt` は関数で、場面によって変わる）
- `setEp(n)` で話を切り替えると、`EP`・`CH`・`S`・`KEY` がその話を指し、端末・地図・ハッシュ比較・つかんだ証拠・侵入の場面の一時的な状態は消える（`resetTemp`）
- `S`（保存データ）：`cur`（章）, `done`（解いた問題 `'章id-問'` → 表示する答え）, `hints`, `nr`（語りの位置）, `seen`（チャットを開いたか、気づきの一言）, `miss`, `duel`, `copied`
- `CH1` / `CH2`：章データの配列。各章は `id`, `no`, `title`, `theme`, `mark`, `clock`, `where`, `narr`, `chat`（チャットアプリの会話。`me` の名前は 2026 年の章なら透、それ以外はミオ。`quiet`・`tail`・`at`）, `open`（章の始めに開くアプリ）, `steps`, `hints`, `solved`（文字列、または文字列を返す関数）, `apps`。省略できるものに `next`（解明のあとのボタンの文字）, `boot`（前の章から続けて開いたとき章扉に出す起動の表示）, `clock2`（`{at, v}`。`at` 問を解くと時計が `v` まで進む）, `ev`（章に入った時点で手に入る証拠の id）。対決のある章は `foe`・`retreat`, `rebut`, `timeout`, `fuse`（ゲージの見出し）, `taboo`（章を通して出せない証拠 → 返事）を持つ。第二話 第六章は `foe`・`rebut`・`btn`・`pass`・`taboo`
- `narr` の各行は `[話し手, 本文, 'frame', 仕掛け]`。`'frame'` は 2036 年のミオの一言（青で表示）。仕掛けは、その行が出たときに呼ぶ関数（何度呼ばれてもよい形にする）
- `apps` の各要素は `{id, name, icon, title, w, h, flush, html, init, after}`。`html` は文字列か、開いたときに呼ぶ関数。`init` はウィンドウを開いた直後に呼ぶ
- `steps` の各問題
  - どの種類にも付けられるもの：`q`（問題文）, `tag`（「Q5-1」の代わりに出す見出し。「対決」「最後」で始まると対決の扱いになる）, `ev`（解くと手に入る証拠の id）, `lead`（前の問題を解いた直後に語りに流す行。場面が動くところと、対決で言い分を崩した直後の一言・相手の反応に使う）, `memo`（捜査ノートの「わかったこと」に追記される。文字列か関数）
  - `text`：`check`, `traps`
  - `pick`：`n`（枠の数）, `check(sel)`, `shown`（解いたあとに表示する答え。文字列か関数）, `how`（何を押せばよいかの一言）, `btn`（ボタンの文字。今は使っていない）
  - `present`：`answer`（崩せる証拠の id の配列）, `why`（証拠の id → 言い返し）, `hold`（証拠の id → 「まだ出さない」の返事）, `nudge`, `rebut`（その問いだけの決まった言い返し）
  - `choice`・`multi`：`options`, `answer`, `why`
  - `op`：`op`（操作の名前）
- つかめる要素は、アプリの HTML に `data-ev="id"`（と枠に出す短い名前 `data-evt`）で書く。id は章の中で重ならないようにする。頭の文字は、b=ブログの記事、a=管理画面の行、d=下書き、l=位置共有の行、m=メッセージ、h=ハッシュ値の行、p=見取り図の印（p＋印の字）、t=透の投稿、y=定点カメラの年ごとの行、s=時刻表の行、v=榊原の言葉（来訪メモ）、k=事務所メモ。「手元の証拠」のカードは証拠の id そのもの

## 絵

### 共通部品

- 配信の部屋・事務所・防犯カメラの写真・跡地は、部屋や街を 3D 座標（m。x=右、y=奥、z=上）で置き、カメラ位置から透視投影して SVG の多角形にしている。共通部品は `camera`・`draw3d`（`pg` / `box` / `plane` / `stand`）・`camFx`（ぼかし）・`camNoise`（センサーノイズ。seed は固定）・`vignette`（周辺減光）・`wallClock`。id は `svgN` で一意にする。`camera()` の返す関数の `.s(x,y,z)` は、その点の 1m が何 px かを返す
- 人物は `STAND`（身長 1.7m の立ち姿の関節。本人から見て x=右手側、y=前、z=上）を `human()` で 3D に置いて投影し、`shadeHuman()` で部位ごとの色と光・影を付ける。輪郭はぼかしてノイズの下に置く
- 暗い絵にかけるぼかしフィルタには `color-interpolation-filters="sRGB"` を付ける（無いと暗い色が 0 か 13 につぶれ、人影が切り抜きのように見える）
- 車は `car3d(P, eye, at, 型, 色)` で描く。型は `SEDAN` と `KEI`
- 絵の中では呼び出しごとに変わる乱数を使わない（位置や大きさは順番から決める）

### 各絵と、手がかりのための制約

- `roomSVG(opts)`：配信画面の部屋（`dark`, `figures`, `seam`, `noflick`）。奥の壁に左から押入れ・時計（鏡文字、針は 3 時 35 分）・窓（鏡文字の看板、その左に踏切）。映像は左右反転している
  - 暗い録画は通常の絵に黒を重ね、その上に人影（`roomFigures`）を壁よりわずかに明るい色で描く。人影の色は 8〜13 程度で、明るさ補正 ×5 前後で人影、×7 前後で奥の男の画面右側の手首の腕時計が見える。腕時計は文字盤を暗く（6 前後）、縁と針を明るく（13 前後）描く。16 を超えると ×7.5 で白く飛ぶ
  - 奥の男は窓の右脇のカーテンの前に立つ（看板の文字に重ねないため）
  - `seam` は襖の隙間と指だけを上から重ねるので、ほかの画素は `seam` なしの絵と完全に一致する（差分表示の前提）。隙間は差分で光る面積を確保するため、本文の「指一本ぶん」より広く描いている（ユーザーの判断でこのまま）
- `officeSVG`（事務所のうつろ放送。`flower`・`phone`）：反転していない。高架の車は乗用車 4 台とタクシー 1 台で、トラックは描かない。椅子・複合機・棚のファイル・キーボードがある
- `planSVG(印, 注記)`（事務所の見取り図）：印は `[x, y, 字, 説明]` の配列で、押して選べる（半径 18、まわりに透明な当たり判定 60×60）。既定は第一章のカメラの候補 A〜D（`PLAN_CAM`）、第七章では待つ場所の候補 1〜5 を渡す。印 5 は `[62,316]`（入口の左の壁と部屋の角のあいだ、第一章の B の真下）
- `lotSVG`（跡地の定点カメラ。`figure`・`flower`）：ランドリーの看板の上から北向きに見下ろす。区画は手前 5・奥 5 で、男は右端（東）の手前の車止めに座る

## テスト

ローカルに Node を入れず Docker Compose で実行する（Git Bash / PowerShell どちらでも可）。

```
docker compose run --rm test
```

依存（jsdom）は `package-lock.json` の integrity で検証して Docker の名前付きボリュームに入れる（`deps` サービス）。テスト本体（`tools/playthrough.test.js`）はネットワークなし・読み取り専用・非 root で動く。

効果音を「あり」にして（鳴らす場所をすべて通って落ちないこと）、第一話を最後まで解き、タイトルに戻って第二話も最後まで解く。最後に `OK: 全章クリア` と出れば成功（終了コード 0）。どちらかの終章に届かないか、途中の確認（`check(名前, 条件)`）が一つでも通らないか、スクリプトエラーが出ると `NG` で終了コード 1（通らなかった確認の名前が `failed:` に出る）。誤答の返事も途中で表示される。

確かめていること：

- 始まり：つかみが第一話の初回だけ出て、押すと飛ばせ、二度目は出ないこと。章の語りを読み終えるまで最初の疑問が出ず、証拠もつかめないこと。チャットの通知が語りの行に届いてから出ること。第一章で書き方の違いをつかんだあとに透の一言が入ること。第二章の配信が、語りが届くまで黒い画面のままであること
- 証拠をつかむ：正解・誤答・「あと一歩」（誤答に数えない）、枠があふれたときの入れ替え、ヒントを開いてもつかんだ証拠が消えないこと、下の帯のボタンでの判定、ハッシュ値の行をつかむと比較の欄に出ること
- 語り：章を解いたあとの語りの「次へ」、配信の左右反転と語りへの反応、狭い画面のふり（`matchMedia` を差し替える）で気づきの一言が語りを開かず `whisper` に出て「語りを表示」で読めること
- 端末：コマンドの候補と引数の候補、コマンド履歴、`constructor` などを打っても落ちないこと
- 証拠と対決：証拠の数・並び・「新」、証拠ごとの言い返し、別の証拠でも崩せる言い分、出せない証拠、「まだ出さない」、崩した言い分に取り消し線が付くこと、3 回での押し返し（一つ前の言い分だけが戻る）
- ゲージ：時間切れ（`fuse=1;fuseTick()` で時計を直接進める。jsdom はタブが隠れた扱いになるので、見えていることにしてから呼ぶ）、語りの続き・メニューで止まること、語りの猶予が 20 秒までであること、言い分がまだ出ていないあいだは減らないこと、時間制限を切る設定
- 第二話：途中で現れるアプリ（端末・来訪メモ）、侵入の場面の「写さない道」と「写して自分で消す道」（保存データを戻して両方を通す）、回線のグラフの 1 分送り、第六章で語りを読むまで架純の疑問が出ないこと・「何も出さない」が誤答に数えられないこと、第七章の準備と時計の早回し、エンディングの一行と記録、メニューでの効果音の切り替え

音・画面の揺れ・見た目・タップは jsdom では確かめられない。

## 見た目とスマホの確認

- 見た目（SVG・レイアウト）は、Playwright 公式イメージ（digest 固定）の Chromium を CDP で操作してスクリーンショットで確かめる（npm パッケージは入れず Node 標準の fetch / WebSocket を使う）。和文フォントを読み取り専用でマウントして `fc-cache -f` する。Chromium には `--disable-dev-shm-usage` を付ける。確認用スクリプトとフォントはリポジトリに入れない。PC 幅は 1920×1000 を基準にする
- スマホは、Chromium のタッチのエミュレーション（CDP の `Emulation.setTouchEmulationEnabled` と `Input.dispatchTouchEvent`、390×800 など）で確かめる。iPhone の Safari がタップの最中に現れた要素でクリックを取り消す動きは、エミュレーションでは再現しないので、コードを読んで確かめる
- 途中の章を直接開くには、保存データ（`utsuro-save-v5`・`utsuro2-save-v3`）の `done` に、それより前の章の全問を入れておく
