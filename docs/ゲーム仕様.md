# ゲーム仕様（game/index.html）

単一HTML・外部ライブラリなし。ブラウザで直接開けば動く。ローカルでは `docker compose up` で http://localhost:8080/ に配信できる（nginx、`tools/nginx.conf`）。公開は GitHub Pages（`.github/workflows/deploy.yml`）。第一話「無人放送」と第二話「不在証明」の二つの話を収め、タイトル画面で選ぶ。進行状況は話ごとに localStorage に保存する（第一話 `utsuro-save-v5`、第二話 `utsuro2-save-v2`。古いキーのデータは読まない）。話をまたぐ設定（対決の時間制限のあり・なし）は `utsuro-pref-v1` に持つ。

CSP は `index.html` 冒頭の meta で指定している。外から読むのは Google Fonts だけで、それ以外の外部通信・外部スクリプトは使えない。新しく外部のものを読むときは CSP も直す。

## 画面

画面内デスクトップ型。章ごとに「その時代の端末」のデスクトップが開き、アプリをウィンドウで開いて調べる。

- タイトル画面（`#title`、話を選ぶボタン `#start`・`#start2`）→ 章扉（`#card`）→ デスクトップ（`#screen`）。第一話は、序章が 2036 年のミオの事務所の端末（明るいテーマ `y2036`）、第一章以降が 2026 年の透のノートPC（暗いテーマ `y2026`）。第二話は、事務所の場面が `y2036`、ネットカフェ・跡地・自宅の場面がミオの古いノートPC（暗いテーマ `mio`、壁紙は足跡）
- デスクトップ: 左にアイコン（`#icons`）、ウィンドウ（`#wins`、ドラッグ・リサイズ・最小化）、下に語り（`#narr`、クリックで一行ずつ進む）、タスクバー（`#bar`、事件ファイルメニュー・開いているウィンドウ・時計）
- 小問は「捜査ノート」アプリ（`data-win="note"`）に出る。答えるたびに次の問題までスクロールし、正解した問題は一瞬光る。答え方は、文字を打つもののほかに、次の三つがある
- 証拠をつかんで結びつける（`pick`）：問題が `pick` のあいだ、開いているウィンドウの中の「つかめる要素」（`data-ev` の付いた記事・表の行・メッセージ・カード・見取り図の印）が点線で囲まれ、押すとノートの枠（`.slots`）に入る。もう一度押すか、枠の×で外れる。枠がいっぱいのときは、いちばん古いものと入れ替わる。そろえて「結びつける」（枠が一つなら「ここに決める」）で判定する。正解だけでなく同じ種類の要素はすべてつかめる（正解だけ光ると総当たりになるため）。ハッシュ値の行は、つかんだ2行がそのまま比較の欄にも出る。幅 760px 以下ではノートが別のウィンドウの裏に回るので、つかんだものを下の帯（`#pickbar`）に出し、「ノートへ」で戻る。キーボードでは Tab で要素に移り Enter でつかむ
- 証拠を突きつける（`present`、対決）：その話でここまでに集めた証拠（問題を解くと手に入る。解いた問題の下に「手に入れた証拠」と出る）の一覧から、一つ選んで突きつける。題だけを並べ、選んだものの中身を開く。相手の言い分とゲージはノートの上に貼りついたままになり、言い返しはそのすぐ下に出る
- アプリの中の操作で解く（`op`）：第二話 第四章の終わり。答えの欄はなく、端末で接続を切ったときに解いたことになる
- チャットは自動では開かない。通知（`.toast`）とアイコンの未読の印で知らせ、初めて開いたときだけ入力中の表示をはさんで一通ずつ届く（`S.seen`）。前に届いたメッセージを読み返すだけのチャット（`quiet:true`、第二話）は、通知・未読の印・入力中の表示を出さない
- 端末は ↑↓ でコマンド履歴を呼び出せる。映像（`.zoomable` の中の `.stream`）は、クリックした場所を拡大できる（第一話の 10/11 の録画、第二話の事務所の録画・定点カメラ・週刊誌の写真）
- 第一話・第二章の配信は録画を再生できる（`initLive`）。11分を20倍速で流し、03:38 と 03:41 に通過音（画面が小さく揺れ、キャプションが出る）、03:44 に黒くなる。音は Web Audio で合成し（50Hz のハム音と低いノイズ。外部の音声ファイルは読まない）、初めは OFF。「左右反転」で映像を鏡に映した向きに直せる
- アプリの中で何かに気づく操作をすると、語りに一言だけ差しこむ（`react(key, 行)`。話ごとに一度きりで `S.seen['r-…']` に持つ。読みかけの語りの続きはそのあとに残る）。左右反転、録画を最後まで再生、解析IDの逆引き、最古の保存版、ハッシュ値の一致、明るさ補正 ×5 以上、差分表示、回線の記録の 10/11
- 対決（`tag` が「対決」「最後」で始まる問題）は、3回まちがえると相手が立て直し（章の `foe`・`retreat` のせりふ）、その章の対決を最初からやり直す。まちがえた数は `S.duel[章id]` に持つ
- 対決のあいだは、相手がしびれを切らすまでの残り時間をゲージで出す（ノートの問題の中と、画面の上端の細い線 `#fuse`）。一つの言い分につき 90 秒（`FUSE_MAX`）。切れたら 1 回まちがえたのと同じ扱いにして相手の一言（章の `timeout`）を語りに出し、ゲージを戻す。正解でも誤答でもゲージは満タンに戻る。タブが隠れているとき、メニュー・タイトル・章扉・エンディングが出ているとき、語りに読んでいない続きがあるときは止まる。「事件ファイル」メニューの「対決の時間制限：あり／なし」で切り替えられる（`prefers-reduced-motion` のときは初めから「なし」）
- 第二話 第四章の終わりは、ミオの古いノートPCの端末で警備会社のサーバーに入る場面（`breach`）。`connect tohto-sec` → `ls`（日付の一覧）→ `ls 0928`（その日に動きを検知した時刻）→ `play 0928 0037` と `play 1011 0421`（映像が端末の中に出る）→ `copy` するかしないかを選ぶ → `wipe`（入った跡を消す）→ `exit`。写しを持ったままでは切れず、`delete` で自分で消すことになる。一度でも写したかは `S.copied` に残り、第六章・第七章の返事、エンディングの透との会話、「この話の記録」が変わる。コマンドはすべて架空のもので、実在の手口は書かない
- 第二話 第七章は、対決の前に「準備」の問題がある。見取り図の 1〜5 から待つ場所を選ぶ（正解はカメラの真下）。決めると画面の時計が 00:10 から 03:41 まで早回しで進み（章の `clock2`）、榊原が来る
- ウィンドウの大きさは右下のつまみ（`.rz`）で変える。CSS の `resize` は、大きい画面で `zoom` をかけるとポインタより大きく動くので使わず、移動と同じくマウスの移動量を拡大率で割っている。章を切り替えたら前の章の通知は消す
- 幅 760px 以下ではアイコン・ウィンドウ・語りを縦に並べ、ウィンドウは一枚ずつ残りの高さいっぱいに開く。通知はタイトルバーの下に出し（×ボタンをふさがないため）、ウィンドウを開いたら消す。アイコンは 6 個まで一列に収め、タスクバーのボタンはアイコンだけにする。表は折り返して幅に収め（右の列の手がかりに気づけるように）、地図は縮めず横スクロールにして中央から見せる。文字の入力中は語りをしまい、入力欄から離れて 0.5 秒後に戻す（先に戻すとタップ位置がずれるため。iPhone はタップ中に仕掛けた 0.4 秒以内のタイマーで要素が現れるとクリックを取り消すため、それより長くする）
- タッチ操作（`pointer:coarse`）では、ウィンドウのボタン・端末のコマンド候補・ヒントのボタン・スライダーを大きくし、入力欄の文字を 16px にする（iPhone が入力のたびに画面を拡大しないため）。語りを続けてタップしても拡大しないよう `touch-action:manipulation` にしている
- 入力欄（解答・端末・地図の検索）は自動入力・自動修正を切っている。iPhone の Safari は `autocomplete="off"` を無視してパスワードなどを出すことがあるので、名前を `search-…` にしている（Safari は名前に search を含む欄に自動入力しない）
- 大きい画面（4K など）では、`#screen` と全面表示（`.over`）に `zoom` をかけて UI を段階的に拡大する（2400×1250 以上で 1.25 倍 … 3840×2000 以上で 2 倍）。基準はフル HD。ウィンドウのドラッグは、マウスの移動量を拡大率で割って CSS の px に直している
- スマホでの操作は、jsdom ではタップや表示を確かめられないので、Chromium のタッチのエミュレーション（CDP の `Emulation.setTouchEmulationEnabled` と `Input.dispatchTouchEvent`）で確認する
- エンディングは全面表示（`#endov`）。第一話の終わりには第二話へ進むボタン（`#toEp2`）、第二話の終わりにはタイトルに戻るボタン（`#endTitle`）がある。「最初からやり直す」は今遊んでいる話だけを消す

## 構造

- `EPS`：話ごとの設定。`key`（保存キー）, `title`, `file`（事件ファイルのメニューの見出し）, `ch`（章データ `CH1` / `CH2`）, `ending`（終章の HTML を返す関数 `ending1` / `ending2`）, `evid`（証拠の一覧 `EV1` / `EV2`。id → [題, 中身]）, `term`（端末の `cmds`・`fallback`・`banner`・`chips`。`chips` は入力の候補を返す関数で、場面によって変わる）。`setEp(n)` で話を切り替えると、`CH`・`S`・`KEY` がその話を指し、端末・地図・ハッシュ比較・つかんだ証拠・侵入の場面の一時的な状態は消える（`resetTemp`）
- `S`（保存データ）：`cur`（章）, `done`（解いた問題 → 表示する答え）, `hints`, `nr`（語りの位置）, `seen`, `miss`, `duel`, `copied`
- `CH1` / `CH2` 配列：章データ。各章は `id`, `no`, `title`, `theme`, `mark`（壁紙の右下の透かし文字。2026年の章は壁紙の中に ghostwire の文字があるので空）, `clock`（作中の日時）, `where`, `narr`（語り）, `chat`（チャットアプリの会話。`me` の名前は 2026 年の章なら透、それ以外はミオ）, `open`（章の始めに開くアプリ）, `steps`, `hints`, `solved`（文字列、または文字列を返す関数）, `apps`。省略できるものに `next`（解明のあとのボタンの文字）, `boot`（前の章から続けて開いたとき章扉に出す起動の表示）, `clock2`（`{at, v}`。`at` 問を解くと時計が `v` まで進む）, `ev`（章に入った時点で手に入る証拠の id）。対決のある章は `foe`・`retreat`（3回まちがえたときのせりふ）, `rebut`（決まった言い返しの配列）, `timeout`（時間切れの一言）, `fuse`（ゲージの見出し）, `taboo`（章を通して出せない証拠 → 返事）を持つ
- `narr` の各行は `[話し手, 本文, 'frame']`。`'frame'` は 2036 年のミオの一言（青で表示）。章を解くと `solved` の段落も語りに流れる
- `apps` の各要素は `{id, name, icon, title, w, h, flush, html, init, after}`。`html` は文字列か、開いたときに呼ぶ関数。`init` はウィンドウを開いた直後に呼ぶ（地図・端末・ハッシュ比較・差分・明るさ補正・映像の拡大 `initZoom`・回線の記録 `initNet`・Web 検索 `initSearch`）。`after:n` を付けたアプリは、その章の問題を n 個解いたあとにアイコンが現れる（第二話 第四章の端末、第五章の来訪メモ）
- `steps` の種類
  - `text`：自由入力。`check(v)` で判定（入力は NFKC 正規化・空白除去・小文字化済み）。`traps` は [正規表現, 誤答時のメッセージ]
  - `pick`：証拠をつかんで結びつける。`n`（枠の数）, `check(sel)`（つかんだ id の配列を受け、正解なら `true`、誤答なら返事の文字列、あと一歩なら `{hold:文字列}` を返す。hold は誤答に数えない）, `shown`（解いたあとに表示する答え）, `how`（何を押せばよいかの一言）。つかめる要素はアプリの HTML に `data-ev="id"`（と枠に出す短い名前 `data-evt`）で書く。id は章の中で重ならないようにする（b=ブログの記事、a=管理画面、l=位置共有、m=メッセージ、h=ハッシュ値、p=見取り図の印、t=透の投稿、y=定点カメラ、s=時刻表、v=榊原の言葉、k=事務所メモ。第二話 第六章のカードは証拠の id そのもの）
  - `present`：証拠を突きつける（対決）。`answer`（崩せる証拠の id の配列）, `why`（証拠の id → 相手の言い返し）, `hold`（証拠の id → 「まだ出さない」の返事。誤答に数えない）, `nudge`（決まった言い返しに添える、次に見るところ）。`why` にも章の `taboo` にもない証拠には、章の `rebut` から順に言い返しを出す
  - `op`：アプリの中の操作で解く。`op` に操作の名前（`breach`）を書き、アプリの側が `solve(c, i, 表示する答え)` を呼ぶ
  - `choice`：単一選択（ラジオボタンの一覧）。`answer` は選択肢のインデックス。`why(i)` が誤答メッセージ。`multi`：複数選択。`answer` はインデックス配列。`why(sel)`。一覧から選ぶ問題は総当たりで解けてしまうので、第二話の3問（「。」の理由、柊が映像を出せない理由、持ち主を来させる方法）だけに残している
  - どの種類にも付けられるもの：`tag`（「Q5-1」の代わりに出す見出し。「対決」「最後」で始まると対決の扱いになる）, `ev`（解くと手に入る証拠の id）, `lead`（前の問題を解いた直後に語りに流す行。場面が動くところに使う）, `memo`（捜査ノートの「わかったこと」に追記される。文字列か関数）
  - 対決の `why` は、相手（久我・榊原）の言い返しの形で書く（「久我「…」 ― 次に見るところ」）
- `hints` は問題ごとの配列（`hints[i]` が `steps[i]` のヒント。1〜2 個を順に開く）。いま解いている問題の中に「ヒントを見る」が出る。開いた数は `S.hints['章-問']` に持つ。開くときはヒントの欄だけを書き換える（ノート全体を作り直すと入力途中の答えが消えるため）
- 誤答の数（`S.miss`）と開いたヒントの数は、エンディングの最後に「この話の記録」として出す（`recordHTML`）。タイトル画面のボタンは、全問を解いた話に「解決済み ・ 読み返す」と出す
- アプリの特殊UI
  - `#mapapp`：地図（`PLACES` 配列、`mapSVG`、`placeCard`）
  - `#tout`：疑似ターミナル（`TERM` オブジェクトがコマンド → 出力）
  - `#htab`：ハッシュ比較（`HASH` 配列）
  - `#dbox`：差分表示（`mix-blend-mode: difference`）
  - `#br`：明るさ補正スライダー
- 絵（配信の部屋、事務所、防犯カメラの写真、跡地）は、部屋や街を 3D 座標（m）で置き、カメラ位置から透視投影して SVG の多角形にしている。共通部品は `camera`・`draw3d`（`pg` / `box` / `plane` / `stand`）・`camFx`（ぼかし）・`camNoise`（センサーノイズ。seed は固定）・`vignette`（周辺減光）・`wallClock`。id は `svgN` で一意にする。`camera()` の返す関数の `.s(x,y,z)` は、その点の 1m が何 px かを返す
- 人物は `STAND`（身長 1.7m の立ち姿の関節。本人から見て x=右手側、y=前、z=上）を `human()` で 3D に置いて投影し、`shadeHuman()` で部位ごとの色と光・影を付ける。輪郭はぼかしてノイズの下に置く。暗い絵にかけるぼかしフィルタには `color-interpolation-filters="sRGB"` を付ける（無いと暗い色が 0 か 13 につぶれ、人影が切り抜きのように見える）。人影の色は 8〜13 程度（明るさ補正 ×7.5 では 16 前後で白く飛ぶ）。週刊誌の写真の男の影は街灯の位置（`LAMP`）から路面に投影する
- `roomSVG(opts)`：配信画面の部屋。`dark`, `figures`, `seam`, `noflick`。奥の壁に左から押入れ・時計（鏡文字）・窓（鏡文字の看板、その左に踏切）。暗い録画は通常の絵に黒を重ね、その上に人影（`roomFigures`）を壁よりわずかに明るい色で描く（明るさ補正 ×5 前後で人影、×7 前後で奥の男の画面右側の手首の腕時計）。奥の男は窓の右脇のカーテンの前に立つ（看板の文字に重ねないため）。`seam` は隙間と指だけを上から重ねるので、ほかの画素は `seam` なしの絵と完全に一致する（差分表示の前提。呼び出しごとに変わる乱数を使わない）
- 第二話の絵とデータ：`officeSVG`（事務所のうつろ放送。`flower`・`phone`。高架の車は乗用車4台とタクシー1台で、トラックは描かない）、`planSVG(印, 注記)`（事務所の見取り図。印は `[x, y, 字, 説明]` の配列で、押して選べる。既定は第一章のカメラの候補 A〜D、第七章では待つ場所の候補 1〜5 を渡す）、`lotSVG`（跡地の定点カメラ。`figure`・`flower`。区画は手前5・奥5で、男は右端〔東〕の手前の車止めに座る）、`photoSVG`（週刊誌の防犯カメラの写真。足場のシートに「木工務店」と電話番号の下4桁。社名の前半は青いシートで隠す。住所表示は電柱の縦書きの板。`empty:true` は同じ角の 10/11 04:21 の元の映像で、男と足場を描かず、窓の並んだ白い壁と、街灯の下を横切る猫を描く）、`netSVG` / `NETDAY`（来客用の回線の送信量。10/11 の 03:52〜03:57 と 05:14〜05:16 に山）、`SRCH`（Web 検索の結果）、`LOTLOG`（定点カメラに映った十年分の時刻）、`EVID`（第六章で架純に渡すかどうかを選ぶ証拠の id）、`TERM2`（ミオの古いノートPCの端末。`whois`・`curl`・`trace`）、`breach` / `BR` / `BRCLIP`（第四章の侵入の場面のコマンドと、その場かぎりの状態）
- `WALL`：テーマごとの壁紙（SVG）。`y2026` は透のノートPC（配線で描いた幽霊、魚拓の年表）、`y2036` はミオの事務所の端末（首都高とビル、ネットワーク図）。読みやすさを損なわないよう薄く描く
- 終章・続編予告は `endingHTML()`

## テスト

ローカルに Node を入れず Docker Compose で実行する（Git Bash / PowerShell どちらでも可）。

```
docker compose run --rm test
```

依存（jsdom）は `package-lock.json` の integrity で検証して Docker の名前付きボリュームに入れる（`deps` サービス）。テスト本体はネットワークなし・読み取り専用・非 root で動く。

第一話を最後まで解き、タイトルに戻って第二話も最後まで解く。最後に `OK: 全章クリア` と出れば成功（終了コード 0）。どちらかの終章に届かないか、途中の確認（`check(名前, 条件)`）が一つでも通らないか、スクリプトエラーが出ると `NG` で終了コード 1（通らなかった確認の名前が `failed:` に出る）。誤答メッセージも途中で表示される。確かめていること：証拠をつかむ問題の正解・誤答・「あと一歩」（誤答に数えない）・枠があふれたときの入れ替え、ヒントを開いてもつかんだ証拠が消えないこと、ハッシュ値の行をつかむと比較の欄に出ること、配信の左右反転と語りへの反応、対決で証拠を突きつける（別の証拠でも崩せる言い分、証拠ごとの言い返し、出せない証拠）、対決のやり直し、時間切れ（`fuse=1;fuseTick()` で時計を直接進める。jsdom はタブが隠れた扱いになるので、見えていることにしてから呼ぶ）、語りの続き・メニューで止まること、時間制限を切る設定、侵入の場面の「写さない道」と「写して自分で消す道」（保存データを戻して両方を通す）、途中で現れるアプリ、準備の場面と時計の早回し、エンディングの一行と記録。音・画面の揺れ・見た目は jsdom では確かめられない。

## 絵と画面の補足（2026-11-11）

- 対決（`present`）のある章では、語りの右に余地があれば捜査ノートを縦いっぱい・広い幅で開く（`openApp` の `wide`）。証拠の一覧（`.win.wide .evlist`）は二列になる。スマホでは、証拠を選ぶと語りをたたむ（語りを読み終えているときだけ）。「対決 n」の見出しは、上に貼りつく欄（`.duelhead`）の中に置く。広いノートが開いているあいだ、通知は左下に出す
- 証拠をつかむときの強調（`#wins.picking [data-ev]`）は、明るい紙のカード（`.doc`・`.news`）では明るい色のままにする。透ける色を重ねると下の暗いウィンドウが透けて、黒い文字が読めなくなる
- スマホの下の帯（`#pickbar`）には `position:relative; z-index:1` が要る（壁紙と透かし文字が上に重なるため）
- 車は `car3d(P, eye, at, 型, 色)` で描く。型は `SEDAN` と `KEI`。事務所の高架は乗用車4台とタクシー1台で、トラックは描かない
- 地図（`mapSVG`）の街区と建物は、位置から決まる格子で描く（乱数は使わない）。`PLACES` の座標・クリック・検索は絵と独立している
- 見取り図（`planSVG`）の第七章の印 5 は、入口の左の壁と部屋の角のあいだ（第一章の B の真下）
- 確認用: 途中の章を直接開くには、保存データ（`utsuro-save-v5`・`utsuro2-save-v2`）に、それより前の章の全問を `done` に入れておく
- 対決のゲージは、語りに未読の続きがあるあいだも止まるが、一つの言い分につき合計 20 秒まで（`NARR_GRACE`）。上限がないと、語りをわざと読み終えずにおけば時間を使わずに考えられてしまう。猶予はゲージが満タンに戻るたびに戻る
